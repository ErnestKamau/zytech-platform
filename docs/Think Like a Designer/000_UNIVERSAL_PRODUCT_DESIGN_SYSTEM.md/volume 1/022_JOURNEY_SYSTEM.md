# Purpose

A journey is the complete relationship between a user and a product.

Users do not remember individual pages.

Users remember experiences.

Journeys connect multiple flows into one continuous experience.

Every application should be designed around journeys.

---

# Journey Philosophy

Products exist to help users accomplish long-term goals.

Every journey should answer

Why did the user arrive?

What do they hope to accomplish?

How can we help them succeed?

How do we encourage them to return?

Journeys extend beyond individual sessions.

# Anti-patterns

Forcing users to repeat actions.

Resetting progress.

---

# Implementation

Applications consume Journeys.

Journeys consume Flows.

Flows consume Patterns.

Patterns consume Components.

Components consume Recipes.

Recipes consume Tokens.

Applications should never bypass the hierarchy.

---

# Journey Checklist

□ Does the journey solve a long-term user goal?

□ Does it preserve context?

□ Does it support multiple sessions?

□ Does it reduce friction?

□ Is accessibility maintained?

□ Is performance consistent?

□ Can users recover from interruptions?

□ Does it build trust?

□ Can AI understand the journey?

□ Is it reusable?

Only then is the journey approved.
