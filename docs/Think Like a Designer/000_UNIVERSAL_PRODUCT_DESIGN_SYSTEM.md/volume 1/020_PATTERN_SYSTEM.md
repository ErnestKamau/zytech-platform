# Purpose

Patterns solve user problems.

Components solve interface problems.

Patterns combine components into meaningful experiences.

Users never interact with isolated buttons.

They complete tasks using patterns.

Patterns should be reusable across applications.

---

# Pattern Philosophy

Patterns represent proven solutions to recurring user problems.

A good pattern

Reduces thinking

Increases consistency

Improves usability

Supports accessibility

Encourages reuse

Patterns are independent of branding.

Only their appearance changes.

Their purpose remains the same.

# Accessibility

Patterns inherit accessibility from components.

Additional accessibility should be defined where multiple components interact.

Reading order

Keyboard flow

Focus management

Announcements

Touch targets

# Performance

Patterns should

Reuse components

Lazy-load heavy content

Minimize layout shifts

Avoid unnecessary re-renders

Optimize media

Performance begins at the pattern level.

# AI Rules

Respect accessibility

Respect responsiveness

# Best Practices

Design around user goals.

Reuse patterns.

Keep patterns focused.

Document all states.

Support responsiveness.

Support accessibility.

Patterns should simplify development.

# Common Mistakes

# Anti-patterns

One-off patterns.

Hardcoded layouts.

Component duplication.

Hidden interactions.

Page-specific logic.

Patterns should be universal.

Never disposable.

---

# Implementation

Applications consume Patterns.

Patterns consume Components.

Components consume Recipes.

Recipes consume Tokens.

Patterns should never bypass the Design System.

---

# Pattern Checklist

□ Does it solve a real user problem?

□ Is it reusable?

□ Does it use approved components?

□ Are all states documented?

□ Is it responsive?

□ Is it accessible?

□ Is it performant?

□ Is it consistent?

□ Can AI understand it?

□ Can it be reused across products?

Only then is a pattern approved.

---

# Final Principle

Patterns are the language of products.

Components are words.

Patterns are sentences.

Flows are paragraphs.

Applications become complete stories.

The strongest products are not collections of components.

They are collections of reusable, well-designed patterns that users instinctively understand.
