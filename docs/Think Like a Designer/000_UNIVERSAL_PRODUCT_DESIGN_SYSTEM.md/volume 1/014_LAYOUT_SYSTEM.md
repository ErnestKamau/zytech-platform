# Purpose

Layout defines how users experience information.

Components communicate information.

Layouts organize information.

Good layouts reduce cognitive effort.

They help users understand

where they are,

what they are looking at,

what they can do,

and where they should go next.

Every interface begins with layout.

Not components.

---

# Layout Philosophy

Every layout answers one question:

"What is the user trying to accomplish?"

Never design around components.

Design around user goals.

A good layout disappears.

Users focus on their work.

Not the interface.

---

# Layout Principles

Every layout should

Reduce cognitive load

Support scanning

Create hierarchy

Guide attention

Remain responsive

Support accessibility

Scale gracefully

Feel calm

Whitespace is intentional.

Alignment is intentional.

Movement is intentional.

Nothing is accidental.

Every layout is composed from reusable primitives.

Shell

Defines the application frame.

Primary navigation.

Sidebar

Secondary navigation.

Primary content area.

Section

Groups related information.

Container

Controls readable width.

Stack

Vertical flow.

Cluster

Horizontal grouping.

Grid

Multi-column layout.

Split

Two primary regions.

Sidebar Layout

Primary content with supporting panel.

Center

Centers content.

Cover

Full viewport composition.

Frame

Media container.

Reel

Horizontal scrolling region.

Overlay

Floating layer.

Spacer

Creates intentional breathing room.

Primitive layouts are reusable.

Applications compose primitives.

Never invent page structures.

# Layout Checklist

Before approving a layout

□ Does it support the user goal?

□ Is the hierarchy obvious?

□ Is the layout responsive?

□ Does it support accessibility?

□ Does it use approved primitives?

□ Does it follow the grid?

□ Does it respect spacing?

□ Is it reusable?

□ Is performance acceptable?

□ Is documentation complete?

Only then is a layout approved.
